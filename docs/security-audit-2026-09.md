## 三、已修复的缺陷

### 3.1 任意文件读取 + SSRF（高危，`wechat_pay.py`）

**问题**：`_fetch_real_bill()` 直接用 `open(cfg["cert_path"])` 与
`open(cfg["private_key_path"])` 读取配置值，并用 `requests.get(download_url)`
请求接口返回的地址。这两个来源都不可信：

- `cert_path` / `private_key_path` 由 `POST /api/payment/sources` 写入，
- 改造前该接口**无任何鉴权**，同局域网任何设备均可设置，
- `download_url` 来自微信接口响应，无条件信任会把请求引向内网或云元数据地址。

**修复**：
- 新增 `_check_cert_path()`：要求扩展名属于 `.pem/.crt/.cer/.key`，且必须是
  **已存在的普通文件**（挡住把任意文件当证书读）；
- 新增 `_check_download_url()`：要求 `https` + 主机在微信官方域白名单内，
  并按**后缀边界**匹配（`notwechatpay.com` 不会被误判为官方域）；
- 新增 `_validating_redirect_session()`：**逐跳校验**重定向目标。
  说明：直接禁用重定向会让微信 CDN 跳转拿到空响应体，破坏功能，故采用逐跳校验。

### 3.2 受保护路径护栏是死代码（中危，`safe_io.py` + `report.py`）

**问题**：`is_protected()` 只被 `safe_write_*` 调用，而 `safe_write_*` 在
**生产代码中零调用**（仅测试使用）→ 名为「受保护路径白名单」的护栏实际未生效。
与此同时 `report.py` 的 `out_dir` 可外部传入且未做校验，是唯一受请求参数
影响落盘位置的写入点。

**修复**：在报表落盘前强制执行 `is_protected()`，使该护栏真正接在请求可达的
写入点上；`out_dir` 穿越到 `tests/` 等受保护目录会被拒绝并返回 `error`。
（`is_protected` 内部已 `resolve()` 规范化，`..` 与大小写变体无法绕过。）

### 3.3 负现金流被吞成 0，预测偏乐观（中危，`finance.py`）

**问题**：`_f()` 用「非正数取默认值」的收敛函数，把期初现金 `-50,000` 归零，
预测凭空多出 5 万元，结论偏乐观；月均基准支出为负时同样被美化。

**修复**：拆分 `_f()`（如实保留负数）与 `_f_pos()`（仅用于月均基准收入/支出），
期初现金如实参与滚动；新增期初透支提示，并修正总结句避免出现「还能剩 -X 元」。

### 3.4 凭证撞号重试分支零覆盖（测试缺陷，`db_ledger.py` 无代码改动）

**问题**：原有并发测试是**假验证** —— 8 线程 + 8 独立连接，但 SQLite 写事务
本身串行化（配合 `busy_timeout=5000`），根本不会算出相同 `seq`，重试分支从未执行。
实测 6 个独立连接确实都会算出 `seq=1`，说明竞态窗口真实存在。

**结论**：重试代码本身**正确**（用真实 `UNIQUE` 冲突验证可正常递增取号并保持唯一），
故未改动实现，仅补了一个真正覆盖该分支的回归测试。

## 四、鉴权改造

### 4.1 改造前的风险

`main.py` 无任何鉴权中间件，服务默认监听 `0.0.0.0:8000`：

- 同 WiFi 下任何设备可读取全部经营流水、熟客记忆、账单；
- 可通过 `POST /api/settings` 改写 AI 配置；
- 可通过 `POST /api/payment/sources` 写入任意证书路径（即 3.1 的利用入口）；
- CORS 正则只约束浏览器，**不约束 curl / 小程序 / 任何脚本**。

### 4.2 设计与取舍

新增 `auth.py` + `AccessTokenMiddleware`，关键决策：

| 决策 | 理由 |
|------|------|
| **默认关闭**：未设置 `SHOP_ACCESS_TOKEN` 即放行 | 显式 opt-in，升级不会直接断掉既有部署 |
| **只守 `/api/**`** | 页面与 `/static` 放行，浏览器才能加载并渲染「填写令牌」界面 |
| `/api/health` 免鉴权 | 供探活与反向代理健康检查使用 |
| 请求头优先（`X-Shop-Token` / `Bearer`） | 避免令牌出现在访问日志与浏览器历史里 |
| 另支持 `?token=` | 仅供浏览器直接下载报表这类无法自定义头部的场景 |
| `hmac.compare_digest` 恒定时间比较 | 防时序侧信道 |
| 401 补 `Access-Control-Allow-Origin` | 本中间件比 CORS 更靠内层，不补头则白名单内手机浏览器读不到 401 详情 |

### 4.3 启用方式

```bash
# 生成一个高强度令牌
cd server
python -c "import auth; print(auth.generate_token())"

# 启动时注入（Windows PowerShell）
$env:SHOP_ACCESS_TOKEN='把生成的令牌粘到这里'
python -m uvicorn main:app --host 0.0.0.0 --port 8000
```

启用后，在网页版 / 小程序的「设置」页填写同一令牌即可（令牌仅存本机浏览器或
小程序 storage，不会上传）。

### 4.4 前端配套改动

- 网页版 `core.js`：`api()` 统一注入令牌头；401 置位 `state.needToken` 并引导到设置页；
  新增 `getToken/setToken/authHeaders/downloadFile`。
- 网页版报表下载改为带令牌的 `fetch + blob`（`<a href>` 无法自定义请求头）。
- 小程序 `utils/api.js`：`request()` 注入令牌头，401 给出明确文案；
  `wx.downloadFile` 补令牌头；设置页新增令牌输入。
- 小程序 `app.js` 的 `baseUrl` 与 `settings.js` 的令牌输入保持独立，互不影响。

## 七、遗留建议（未实施）

1. **`build/` 产物与依赖版本**：`requirements.txt` 未锁版本，`openai>=1.40`
   这类宽松约束在不同时间安装可能引入行为差异，建议补 `requirements.lock`。
2. **令牌轮换**：当前令牌通过环境变量注入，轮换需重启进程；如需在线轮换可改为
   读取 `config.local.json`（`load_settings()` 已具备热生效能力）。
3. **操作审计**：`/api/settings`、`/api/payment/sources` 这类敏感写操作建议落审计日志，
   便于事后追溯。
4. **`safe_io.safe_write_*`**：目前仍无生产调用方。本次已把护栏接到报表写入点；
   若后续新增动态写文件能力，应统一走 `safe_write_*`，避免护栏再次形同虚设。
