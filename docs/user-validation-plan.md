# 真实用户验证方案（含问卷 / 埋点口径 / 记录模板）

> 诚实前提：**真实用户验证必须由人来做**（找店主真实用一段时间）。本文件提供**可执行的验证方案**
> 与**只读导出工具**，把"用户用得怎么样"变成可填表的数字；仓库内的演示数据**不算**真实验证。

---

## 一、目标与成功标准

| 目标 | 指标 | 达标线（建议） |
|---|---|---|
| 店主真的在记 | 连续使用天数 | ≥ **7 天**内有 ≥5 天记账 |
| 记账不返工 | 「记完核对」里被更正的笔数占比 | ≤ **10%** |
| 人情被接住 | 提醒**送达率** | ≥ **80%** |
| 经营有动作 | 店主完成提醒/采纳文案的次数 | 每周 ≥ **3 次** |
| 值得付钱 | 意愿价（WTP）问卷 | ≥ **50%** 选 ≥ 59 元/月 |

## 二、样本与周期

- **对象**：3~5 位小微实体店店主（早餐/面馆/小卖部/摊主），**非熟人**优先；
- **周期**：每人 **1~2 周**（含 1 次电话/上门开场 + 1 次回访）；
- **方式**：本机 Docker/一键脚本部署；AI Key 由你提供或让店主自填；
- **伦理**：明确"数据只在你自己电脑上、随时可删"，签署一页知情同意（可口头+聊天记录留痕）。

## 三、指标口径（脚本自动算）

`cd server && python ../scripts/validation_report.py --db <真实库> --days 14`
（**只读打开**，不改数据；输出即下面模板的填表数据）

| 指标 | 口径 |
|---|---|
| 记账笔数 / 营业天数 | `transactions` 计数与按天去重 |
| 熟客数 | `customers` 计数 |
| 提醒送达率 | `reminders.send_ok=1 / reminders 总数`（执行闭环） |
| AI 调用与延迟 | `ai_metrics`（次数、tokens、平均延迟、按业务域） |
| 毛利率 / 实际日销 | 收入与「进货」成本；收入 ÷ 有收入的天数 |
| 保本日销 | 单店档案固定成本 ÷ 毛利率 ÷ 30（未建档案则为空） |

## 四、店主问卷（开场前 + 结束时各一次）

**A. 开场（现状基线）**
1. 你店里现在怎么记账？（纸/微信/Excel/不记）
2. 你知道自己店的**保本线**是多少吗？（大概率答不出——这就是钩子）
3. 上个月有没有因为**没记住熟客的事**而后悔？
4. 你发朋友圈一般怎么想文案？
5. 每月在记账/报税/文案上大概花多少钱、多少时间？

**B. 结束（体验后，1~5 分 + 开放）**
1. 语音/文字记账准不准？改过几次？
2. 「今日提醒」有没有帮你想起某位熟客？举一个例子。
3. 「保本线」这一下有没有让你重新看这家店？
4. 哪一处最没用/最烦人？（**要追问具体场景**）
5. **愿意每月花多少钱**用下去？（0 / 29 / 59 / 99 / 199 元）为什么？
6. 会不会推荐给隔壁店主？（0~10 分，NPS）

## 六、从"验证"到"材料"的产出

1. 每位店主的**一页验证报告**（用第四节模板）；
2. **汇总页**：N 位店主的中位数（记账笔数、送达率、WTP、NPS）+ **2 条原话**；
3. **诚实边界**：若只做了 2~3 位、周期 <1 周，要在材料里写明"小样本、探索性验证"，
   不要把结论说成"已规模化验证"。

## 七、我们**不能**替你做的那部分（如实说明）

- 招募真实店主、获得授权、收集真实数据 → **必须你来做**；
- 本仓库提供的：部署方式（Docker/一键脚本）、**只读导出脚本**、问卷与模板、口径定义、
  以及产品侧已具备的"送达留痕 / 采纳真值"（保证数据可被验证，而不是靠回忆）。
