# 「巷子里的AI掌柜」小程序演示教程

面向演示者。目标：**10 分钟内让店主看懂「AI 帮他省了什么」**，并且现场不出意外。

演示对象是小微实体店店主（早餐铺/面馆/小卖部），不是技术评审。
全程用一部手机 + 一台电脑，手机连电脑的局域网。

---

## 一、演示前 30 分钟准备

### 1. 电脑端：起后端 + 查 IP

```powershell
cd server
python -m uvicorn main:app --host 0.0.0.0 --port 8000
```

另开一个窗口查局域网 IP（记下来，下一步要用）：

```powershell
ipconfig | Select-String "IPv4"
```

找到形如 `192.168.1.5` 的那一行（无线局域网适配器）。演示地址就是
`http://192.168.1.5:8000`。

> 演示时**不要设 `SHOP_ACCESS_TOKEN`**。设了就要在小程序里填令牌，白白多一个出错环节。
> 局域网演示环境可接受；如果演示环境不可信，见文末「附录 B」。

### 2. 电脑端：确认防火墙放行 8000

Windows 首次启动 uvicorn 会弹防火墙提示，**必须勾选「专用网络」并允许**。
如果之前点了「取消」，手机就连不上：

```powershell
# 以管理员身份运行，放行 8000 端口（仅专用网络）
New-NetFirewallRule -DisplayName "AI掌柜演示" -Direction Inbound -LocalPort 8000 `
  -Protocol TCP -Action Allow -Profile Private
```

### 3. 配置大模型 Key（决定演示效果，务必先做）

**Key 配在后端，手机不需要配任何模型地址**——手机只连你电脑的后端，由后端去调模型。

最省事的方式：后端启动后，**用电脑浏览器**打开 `http://127.0.0.1:8000`，
进「设置」页填 Key 并保存。也可以直接写文件：

```json
// server/config.local.json（已被 .gitignore 排除，不会误提交）
{ "api_key": "sk-你的Key", "base_url": "https://api.deepseek.com", "model": "deepseek-flash" }
```

保存后**立即生效，不用重启后端**。

> ✅ **本机已配好并实测通过**（配置见 `server/config.local.json`）：
> `base_url = https://api.deepseek.com`、`model = deepseek-flash`；
> 8 项 AI 功能全部实测正常返回。
>
> **模型版本已核对官方文档确认**：`deepseek-flash` 对应
> **DeepSeek-V4.1-Flash**（见 [Models & Pricing](https://api-docs.deepseek.com/quick_start/pricing)
> 的 MODEL VERSION 一栏）。旧名 `deepseek-v4-flash` / `deepseek-v4-flash-vision-exp`
> 仍可调用，但对应模型已下线，请求同样由 V4.1-Flash 承接并按 Flash 价格计费。
> 而 `deepseek-v4`、`deepseek-v4.1-flash`、`deepseek-v4.1` 这些写法**不存在**，填了报 404。
> 想自己核对，可在 `server` 目录执行：
>
> ```
> python -c "import config; from openai import OpenAI; s=config.load_settings(); c=OpenAI(api_key=s['api_key'],base_url=s['base_url']); print([m.id for m in c.models.list().data])"
> ```

> ⚠️ **思考模式已按任务分档开启**（`ai.py` 内实现，你不用手动改）：
> V4.1-Flash 默认开启思考模式且推理强度为 `high`，但本项目多数调用是"把这句话
> 拆成金额和商品"这类简单任务，开思考纯属浪费。实测差异很大：
>
> | 任务类型 | 处理方式 | 实测耗时 |
> |---|---|---|
> | 记账解析、熟客提醒/画像、朋友圈文案 | **关闭思考**（保速度，且保住 temperature 角色差异） | 0.7~6.5 秒 |
> | 经营洞察、单店诊断 | 开思考（low） | 5~30 秒 |
> | 报税建议 | 开思考（high，要答三个问题） | 30~65 秒 |
>
> **演示前一定要知道**：报税建议和经营洞察是**秒级到分钟级**的操作，
> 现场点了要等。建议先讲结论再等 AI 出字，别让店主盯着转圈。
> 另外这些耗时受网络波动影响明显（同一个请求 18~65 秒都出现过），
> **不要用它们掐表演时长**。
>
> 顺带说明为什么默认关思考：思考模式下服务端会**忽略 `temperature`**
> （官方文档明确写了"不报错但也不生效"），而多 agent 编排靠 temperature
> 区分员工角色（创意文案师 0.9 要发散、合规审核 0.2 要稳定）。
> 所以文案与角色类任务必须走非思考模式。
>
> 早先还有过更严重的问题：旧代码按非思考模型设置的输出预算（260~500）会被
> 推理过程吃光、正文返回空串，表现为"AI 功能没反应"。现已在 `ai.chat()`
> 修复（正文为空时自动放大预算重试），并补了回归测试。

> ⚠️ **不配 Key 会怎样**：记账金额和客户仍能识别（规则提取），但商品名解析粗糙
> （`"买了两个肉包一杯豆浆，6块"` 的"事由"会是整句原文而不是"肉包、豆浆"）；
> 文案和报税建议变成模板文本；**多 agent 竞争出稿不会真正运行**。
> 如果你的演示要讲"AI 智能解析""多个 AI 员工竞争出稿"，**必须先配 Key**。
> 界面上的 `✨` 表示真实 AI，`📝` 表示兜底——演示前自己先看一眼，别现场翻车。

### 4. 手机端：导入并配置地址

1. 微信开发者工具导入 `miniprogram/` 目录
2. 本地设置勾选「不校验合法域名」
3. 手机与电脑连**同一个 WiFi**
4. 小程序里进「设置」页 → 最上方**「后端地址」**填 `http://192.168.1.5:8000` → **「测试连接」**
5. 看到 **✅ 连接正常** 才继续

> 真机上 `127.0.0.1` 指向手机自己，用默认值一定连不上。首页这时会出现红色提示条。

### 5. 演示前自检（一条命令）

```powershell
cd server
python ..\scripts\mp_demo_check.py
```

看到「必须修的问题：0」就可以了。它还会提醒插件/appid 等注意事项。

### 6. 清掉演示脏数据

演示要干净的开场。删掉本地数据库会清空所有流水和熟客：

```powershell
Remove-Item server\data\ai_shopkeeper.db -ErrorAction SilentlyContinue
```

> **删之前确认里面没有你要留的数据**。删掉后后端下次启动会自动重建空库。

### 7. 灌入演示数据（**必做**，第 2、5 站依赖它）

演示最多只录入几条数据，账本/熟客/提醒页都会是空的，没法展示。
本步骤灌入**当月 1 日至今**的完整经营数据，让每个页面打开都有内容：

- **经营流水**：当月 1 日至今（约 16 天）× 每天约 200 笔小额消费（共约 3,200 笔）
  —— 按真实菜单（肉包 2 元、豆浆 2 元、小笼包 6 元…）生成，
  **客单价约 6.6 元**，符合早餐铺实际
- **熟客**：10 位，各有标签、常点、光顾次数与消费记录（共 77 笔）
- **记忆点**：12 条店主随手记的暖心细节
- **今日提醒**：3 条待办（演示时可以点 ✓ 完成）

> **为什么是"当月 1 日至今"而不是"最近 14 天"**：房租/水电是**整月**固定成本，
> 若只灌最近半个月，8000 元固定开销会全压在半个月的现金里，
> 经营洞察的现金视角就会说"白忙活"，与单店模型算出的月利润口径打架。

**顺序很重要：先清空，再灌入。** 脚本有幂等保护（已有当月流水时会拒绝执行，
避免数据翻倍），需要重灌就删库或加 `--force`。

```powershell
cd server
Remove-Item data\ai_shopkeeper.db -ErrorAction SilentlyContinue   # 清空旧数据
python ..\scripts\seed_demo_data.py                               # 灌入演示数据
```

跑完会立刻打印核验结果（脚本会自己检查客单价、日销、两个利润口径是否自洽）：

```
  熟客 10 位，记忆点 12 条
  流水 3257 笔
  今日提醒 3 条
  收入 21,120 元 / 3223 笔  客单价 6.6 元  ✅ 餐饮合理区间
  反推：日销 1,320 元 / 营业 16 天 / 毛利率 62.0%
  单店模型：保本日销 860.2 / 目标 1,118.3 / 月利润 8,552.0 / 判定 健康（81）
  月度现金流：收入 21,120 / 支出 17,081 / 结余 4,038
    ✅ 与模型月利润量级一致，洞察结论不会自相矛盾
  ✅ 实际日销高于保本线，单店模型演示结论合理
```

若出现 ❌（客单价异常 / 日销过低 / 两个口径打架），说明数据设计出了问题，
不要直接拿去演示。

> 脚本用日期做随机种子，**同一天运行结果一致**。若想贴近特定业态，
> 改脚本顶部的 `MENU`（菜单与单价）、`BASKET_WEIGHTS`（篮子分布）、
> `DIRECT_COST_RATIO` 与 `CUSTOMERS` 名单。

### 8. 预热缓存（建议做，让现场秒出）

账本页有两块 AI 内容会在页面操作时**自动请求**。它们现在都**按维度缓存**：
第一次要几十秒，之后秒回。建议演示前先花一分钟把它们生成好。

```powershell
cd server
# 经营洞察（按月缓存）
curl.exe -s -X POST http://127.0.0.1:8000/api/orders/insights `
  -H "Content-Type: application/json" -d "{\"year\":2026,\"month\":9,\"refresh\":true}" > $null

# 报税建议（按销售额分 1000 元一档缓存，这里预热 350000 这一档）
curl.exe -s -X POST http://127.0.0.1:8000/api/tax/advice `
  -H "Content-Type: application/json" -d "{\"quarterly_revenue\":350000,\"refresh\":true}" > $null
```

> 月份与销售额按你演示时要用的数字填。用 `refresh=true` 强制按当前演示数据
> 重新生成，避免命中早期数据留下的旧分析。
>
> **预热必须在第 7 步灌数据之后做**。顺序反了，缓存里就是旧数据的分析，
> 现场内容会对不上。

| 内容 | 缓存维度 | 首次 | 命中缓存 | 演示时是否会自动请求 |
|---|---|---|---|---|
| 经营洞察 | 按月份 | 5~30 秒 | **7 毫秒** | 是（进账本页即请求） |
| 报税建议 | 按销售额（1000 元/档） | 30~65 秒 | **毫秒级** | 是（点「算增值税」后请求） |

**若演示中数据变了**：缓存不会自动更新（这是有意的——否则每次进页面都要等）。
需要新分析时，点对应卡片标题行右侧的 **「重新分析」/「重新生成」**。

## 二、演示动线（8 分钟主线）

推荐顺序：**记账 → 熟客 → 文案 → 账本 → 单店模型**。
前四个是"省事"，最后用单店模型收尾最有冲击力——
它会把第 1 站刚记的账变成一条**保本线**，这是全场的记忆点。

> 动线**刻意避开**两个慢接口：「报税建议」（30~65 秒）与「经营洞察」（20~30 秒）。
> 它们留在界面上可用，但不进演示动线，避免让店主干等。

---

### 第 1 站 · 首页记账（约 1.5 分钟）

**做什么**：在首页「不方便说话？直接打字」输入框里输入下面这句，点「记一笔」。

```
王阿姨买了两个肉包一杯豆浆，6块
```

**会看到**：出现「已记下」卡片，显示顾客、事由、金额、分类，以及借贷凭证号。

实测解析结果（真实 AI，可放心对照）：

| 输入 | 解析结果 |
|---|---|
| 王阿姨买了两个肉包一杯豆浆，6块 | 顾客=王阿姨，事由=`两个肉包一杯豆浆`，收入，主营业务收入 |
| 李叔拿了两斤猪肉，38块，支出 | 顾客=李叔，事由=`猪肉两斤`，**支出，分类=进货** |
| 今天卖了差不多八百块 | 金额=800，主营业务收入（口语模糊金额也能取） |

> 第二笔的分类自动落在「进货」很关键——单店模型反推毛利率时，
> 只有「进货」算直接成本。可以顺势讲一句"它知道进货算成本，房租水电不算"。

**等待时间**：单笔约 1~3 秒。连续记两笔没问题。

> 这两笔账在第 5 站会派上用场：单店模型页点「从账本流水带入」时，
> 会把演示数据 + 刚记的这两笔一起算进去，形成"记账 → 反推经营模型"的闭环。
> 所以**第 1 站务必先记这两笔**，别跳过。

**要念的话**：

> 摊主手上沾着油，打不了字。他只要像跟人说话一样说一句，AI 就把这笔账拆开了——
> 谁买的、买了什么、多少钱、该记到哪个科目，还自动生成了会计凭证。
> 熟客不用建档，提到称呼就自动归档了。

**再补一笔**（让账本有数据，后面要用）：

```
李叔拿了两斤猪肉，38块，支出
```

**如果现场卡住**：见附录 A 的「记账没反应」。

---

### 第 2 站 · 熟客记忆（约 2 分钟）

**做什么**：
1. 进「熟客」页 —— **已经预置了 10 位熟客**，每位都有标签、常点、光顾次数
2. 点开「王阿姨」看详情（2 条记忆点 + 消费记录）
3. 在记忆输入框补一条 `孙子考了一百分`，保存
4. 回到列表，演示顶部「今日要惦记的事」的 3 条提醒，点一条的 ✓ 完成

**会看到**：

| 内容 | 现场样子 |
|---|---|
| 熟客列表 | 10 人，如「小周 `外卖骑手` 常点：煎饼和豆浆（光顾 4 次）」 |
| 熟客详情 | 记忆点 + 消费记录（王阿姨：孙子考上一中 / 胃不好，豆浆要热的） |
| 今日提醒 | 3 条待办：王阿姨（问孙子适应不适应）／张叔（老伴住院）／李叔（工地要搬走） |

**要念的话**：

> 小店最值钱的不是账本，是"人情"。你看这几条——王阿姨孙子考上高中、张叔老伴住院、
> 李叔工地要搬走。**这种细节店主自己记不住**，但记下来，下次人来了就能顺口问一句。
>
> 熟客为什么一直来？不是因为便宜，是因为"他记得我"。这个工具就是替店主记住这些事。

**可以补一条新记忆点**（现场感更强）：给王阿姨填 `孙子考了一百分` 并保存，
然后说"以后她一来，提醒里就会带上这条"。

**若想演示 AI 生成提醒**：点「✨ 一键生成今日提醒」（约 1~2 秒），
它会基于记忆点生成新的提醒。原先是 3 条预置，生成后会变成 AI 产出的内容。

---

### 第 3 站 · 朋友圈文案（约 1.5 分钟）

**做什么**：进「文案」页 → 店名填 `巷子里的早餐铺` → 场景选「今日营业」→ 点「生成」。

**会看到**：1~3 条可直接发的文案（真实 AI 时是多个"AI 员工"竞争出稿、掌柜融合）。

**要念的话**：

> 店主最烦的就是发朋友圈——想发又不知道写什么，写出来还一股网红味。
> 这里不是让一个 AI 写，是让"创意文案师"和"熟客运营"两个 AI 员工**各写一版**，
> 再让"合规审核"挑毛病，最后掌柜融合成一条能直接发的。挑一条复制就能用。

**这是多 agent 编排的展示点**。如果配了 Key，界面上会有 `✨` 标记。

**等待时间**：约 5~10 秒（要跑 4~5 次模型调用：两位员工出稿 → 合规审核 → 掌柜融合）。
演示时可以先点「生成」，再讲"背后有 3 个 AI 员工在同时干活"，讲完刚好出结果。

---

### 第 4 站 · 账本与算税（约 2 分钟）

**做什么**：进「账本」页，依次点顶部 4 个标签：**流水 / 算税 / 科目 / 报表**。

**会看到**：
- **流水**：半个月的经营流水，带借贷凭证（演示前已灌入演示数据，见下文说明）
- **算税**：增值税（小规模）、个税、企税、报税提醒
- **科目**：66 项会计科目表
- **报表**：一键下载 Excel（可当场导出发给店主）

**要念的话**：

> 店主不用懂会计。但税务局要的东西一样不能少：增值税、附加税、个税、企税，
> 还有报税日历提醒你别逾期。这里全算好了，报表点一下导出 Excel，直接给代账会计。

**现场算一个**（**秒出**，放心点）：算税页填季度销售额 `350000` → 点计算。
显示超过 30 万免征线、应缴增值税 `10194.17` 元（价税分离口径）。
再填个税月薪 `15000` → 税额 **790 元**。都是一点就出。

**等待时间**：本页除「经营洞察」和「报税建议」两块外**全部瞬时**（实测 2~7 毫秒）。

**「经营洞察」现在可以讲了**（原先是 20~30 秒，已改为按月缓存）：
- 若你做过「第 8 步：预热洞察缓存」，打开账本页它就**秒出**（实测 7 毫秒）——
  可以顺势讲一句"AI 每个月给你一份经营体检"
- 内容质量不错，实测会把数据算成大白话，还会挑出异常。例如演示数据下它会说：
  *"这个月收了 18732，花了 15710，净剩 3022……每卖 100 块，真正落兜里的只有 16 块左右"*，
  并指出"水电费 2000 块，一个月就 1 笔，在小店里面偏高了"
- ⚠️ **如果演示中又记了新账，缓存不会自动跟着变**。需要新分析时点标题行右侧的
  **「重新分析」**（约 5~30 秒）。演示时别指望它会自己更新

> ⚠️ **「报税建议」不进演示动线**：它要回答"交多少/有无节税空间/下季度注意什么"
> 三个问题，首次生成实测 **30~65 秒**，节奏上不划算。
> 但如果你在第 8 步预热过 350000 这一档，现场点「计算」时它会**秒出**
> （命中同档缓存）——那样就可以讲了。否则别点。

### 第 5 站 · 单店模型（约 2.5 分钟，压轴）

这一站的关键是**用第 1 站刚记的账，自动推出这家店真实的经营状况**——
不是让店主手填数字，而是"你记的账，AI 帮你算出了保本线"。

**做什么**：

1. 进「单店模型」页 → 业态选「餐饮」
2. 点 **「📖 从账本流水带入」** 按钮 ← **本演示的核心动作**
3. 页面会自动填入实际日营业额与毛利率，并显示一行来源说明

**会看到**（基于演示数据实测，可放心念）：

| 项目 | 数值 |
|---|---|
| 从账本反推 · 收入合计 | 21,126 元 |
| 从账本反推 · 直接成本 | 8,063 元 |
| 从账本反推 · 营业天数 | 16 天 |
| **实际日销**（自动填入） | **1,320 元** |
| **毛利率**（自动填入） | **61.8%** |
| 保本日销 | 863 元 |
| 目标日销 | 1,122 元 |
| 月利润 | 8,478 元 |
| 回本周期 | 21.2 个月 |
| 综合判定 | **健康（81 分）** |

> 上表是「灌入演示数据 + 第 1 站手记两笔」之后的现场值。
> 房租/人工/水电若为空，补上 `6000 / 8000 / 2000`（与演示数据一致），
> 上面这组结论才成立。

**要念的话**（这是整个演示的记忆点）：

> 刚才记的那几笔账，不是记完就躺着了。点这一下，它把本月的真实流水翻出来算了一遍：
> 一天实际卖 1,320 块，毛利率 61.8%。
>
> 再结合房租、人工、水电，算出这家店的**保本线是每天 863 块**。
> 现在卖 1,320，过了保本线也过了目标线，所以判定是健康。
>
> 反过来想——哪天日销掉到 860 以下，就是开门一天亏一天。
> **这就是店主平时算不出来、却决定生死的那条线。**

**加演（秒出，很有说服力）**：把「实际日营业额」手动改成 `600` 再点计算。

> 结论立刻翻转为**危险（16 分）**，会说："实际日销 600 元低于保本线 863 元，
> 每开一天门都在往里面搭钱——这不是生意，是烧钱。"

**等待时间**：
- 「从账本流水带入」是查数据库，**10 毫秒级**，秒出
- 模型计算是**纯本地算法**，秒出
- 只有页面下方「经营诊断」要调 AI（5~30 秒）。建议先把上面这些秒出的数字讲透，
  诊断文字出来再补一句；赶时间就跳过

> ⚠️ **不要让店主对着空账本点「从账本流水带入」**。若账本里只有零星两三笔，
> 反推出的日销会很低、毛利率甚至为负（成本大于收入），现场会很难看。
> 演示前务必灌入演示数据——见「一、演示前准备」第 6 步。

## 四、附录 A · 现场故障排查

### 首页出现红色「连不上后端」提示条

按可能性从高到低查：

1. **后端地址填错** → 设置页看「当前」是不是电脑的局域网 IP，点「测试连接」
2. **手机和电脑不在同一 WiFi** → 手机检查 WiFi 名称（注意别连了 5G 访客网络）
3. **电脑防火墙拦了** → 见准备清单第 2 步
4. **后端没起来** → 电脑上开 `http://127.0.0.1:8000`，能打开就说明后端正常

### 记账没反应 / 转半天

- 看首页红色提示条（连接问题）
- 如果只是"事由"识别得粗糙 → 正常，说明没配 Key，走规则兜底
- 提示"金额没听清，只记了流水" → 换一句带明确金额的话，比如"王阿姨买包子 6 块"

### 某个 AI 按钮点了转很久

先分清哪些是**本地瞬时**、哪些是**要等模型的**：

| 瞬时（可放心现场点） | 需等待 |
|---|---|
| 保本线/目标日销/回本周期/现金流 | 记账解析 1~3 秒 |
| 增值税/个税/企税/附加税计算 | 熟客提醒/画像 1~2 秒 |
| 66 科目表、报税日历、流水查询 | 朋友圈文案 5~10 秒 |
| 报表导出 | 单店经营诊断 5~30 秒 |
| **经营洞察**（已预热，约 7 毫秒） | 经营洞察**首次生成** 5~30 秒 |
| **报税建议**（预热过同档销售额，毫秒级） | **报税建议首次生成 30~65 秒** |
| | 点「重新分析」/「重新生成」5~65 秒 |

文案生成慢是正常的：多 agent 会**串行调用 4~5 次模型**（两位员工出稿 → 合规审核 → 掌柜融合）。
别在等待时以为卡死了，界面上有「生成中…」状态。

**耗时受网络波动影响很大**——同一个报税建议请求，实测出现过 18 秒和 65 秒两种情况。
所以演示时**不要用它来掐时间**，也别说"几秒就出来"。

### 界面显示空白 / AI 没反应

按顺序排查：

1. **看首页有没有红色提示条** → 有就是连不上后端，去设置页配地址
2. **看数字是不是全是 0** → 可能是数据库被清空了，重新灌演示数据（第 7 步）
3. **AI 功能没反应** → 检查「设置」页顶部是否为"已开启 · AI 生效中"；
   显示"兜底模式"说明 Key 没配上，此时文案/提醒会返回模板文本
4. **账本页洞察是旧内容** → 这是缓存，点「重新分析」刷新
5. **报「需要访问令牌」** → 后端设了 `SHOP_ACCESS_TOKEN`，见下一条

说明后端设了 `SHOP_ACCESS_TOKEN`。要么去掉这个环境变量重启后端，
要么在小程序「设置」页填入同一令牌。

### 「语音功能需正式AppID授权」

**当前 `app.json` 没有声明「同声传译」插件**，所以语音按钮不可用是预期行为，
会降级为手动输入。这不影响其它功能演示。

要让语音真的能用，需要两步（都在小程序侧，与后端无关）：
1. 在「设置-第三方设置-插件管理」中添加「同声传译」插件（appid `wx069ba97219f66d99`）
2. 在 `miniprogram/app.json` 增加：

```json
{
  "plugins": {
    "WechatSI": { "version": "0.3.4", "provider": "wx069ba97219f66d99" }
  }
}
```

> 版本号以微信公众平台「插件管理」里显示的为准（社区文档普遍是 `0.3.4`，
> 若后台显示更高版本，按后台填）。插件主页：
> [微信同声传译](http://mp.weixin.qq.com/wxopen/pluginbasicprofile?action=intro&appid=wx069ba97219f66d99)
>
> 需要用**正式 AppID**。「测试号/游客 appid」无法使用插件。
> 演示前请确认这两步是否已做——没做的话，**把"按住说话"从演示脚本里去掉**，
> 直接讲手动输入，不要现场点语音按钮。
>
> 若语音报错 `retcode -30001 / -30012`，通常是用户未授权录音权限，
> 需要在页面放一个 `open-type="openSetting"` 的按钮引导用户去设置页开启。

项目里 `pages/index/index.js` 已经按官方用法接了插件，且做了降级保护：
`requirePlugin` 抛错时不会崩溃，只是把语音按钮置灰并提示改用手动输入。

### 关于演示环境安全

局域网演示不设令牌是方便，但要清楚代价：**同一 WiFi 下任何设备都能读写这本账**。
如果演示在咖啡厅、共享办公、展会等不可信网络，请开启令牌：

```powershell
cd server
python -c "import auth; print(auth.generate_token())"   # 生成令牌
$env:SHOP_ACCESS_TOKEN='把令牌粘这里'
python -m uvicorn main:app --host 0.0.0.0 --port 8000
```

然后在小程序「设置」页填同一令牌。多一步操作，换来的是账本不外泄。

更彻底的做法是演示时用**手机热点**：电脑和手机都连这个热点，
网络里只有你自己的两台设备，既不设令牌也安全。
