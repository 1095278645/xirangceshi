# 一人公司的 AI 员工编制表 · 执行闭环 · ROI 与定价

> 面向 OPC（One Person Company，一人公司）场景：**一个人开店，AI 顶几个岗位。**
> 每一行都标注**自动化程度**（全自动 / 半自动 / 需人工），不夸大。
> 数据口径：`/api/metrics/ai` 的 `roi` / `evolution` 分块（本机真实用量 + 可配置的参考人力价）。

## 一、AI 员工编制表（7 个岗位）

| 岗位 | 职责 | 触发方式 | 产出 | 自动化程度 |
|---|---|---|---|---|
| 🏮 **掌柜**（裁决/复盘） | 汇总全店事实 → 只挑"今天最该干的一两件" | 每日定时 + 首页「让掌柜再看一遍」 | 一段口语化复盘 + 可展开的原始事实 | 复盘**全自动生成**；决策由人拍板 |
| 🧾 **账房先生**（记账/凭证/报表） | 口语记账 → 客户/商品/金额/科目 → 借贷凭证 | 每次记账自动 | 流水 + 凭证号 + 三表 + Excel | ✅ **全自动** |
| ❤️ **熟客管家**（记忆/提醒/画像） | 自动建档、记细节、生成今日提醒并**送达** | 记账时自动建档；提醒每日自动生成 | 熟客档案 + 今日提醒（**自动投递 + 留痕**） | 生成/送达**全自动**（见第二节闭环） |
| ✍️ **创意文案师 + 熟客运营** | 两条并行出稿，合规审核挑毛病，掌柜融合 | 「文案」页手动点生成 | 可直接发的朋友圈正文 | ⚠️ **半自动**（需人点一次） |
| 📦 **采买师傅**（库存进销存） | 商品档案、入库/出库/盘点、补货/过期预警 | 「更多 → 库存」手动操作 | 货值、见底/临期清单 | ⚠️ 预警自动，登记需人工 |
| 🧮 **税务管事**（算税/报税建议） | 增值税/附加税/个税/企税 + 报税日历 | 「账本 → 算税」手动 | 税额 + 建议 + 申报提醒日历 | 计算 ✅ **全自动**；建议 ⚠️ 半自动 |
| 🔍 **经营监察**（异常/更正审计） | 大额/边界护栏、账目更正留痕、低于保本线预警 | 每次记账自动校验；每日预警 | 预警 + 审计记录 | 校验/预警 ✅ **全自动**；处置需人工 |

> 一句话：**"账、客、税、警"已全自动；"文案、采买、建议"是人点一下的副手。**

## 二、执行闭环（本次补齐的"真扣分点"）

原状态：提醒生成后**躺在列表里，没人接**（网页端甚至没有提醒 UI）。
现在形成闭环：

```
生成（AI） → 送达（自动选通道） → 留痕 → 未送达次日自动重试 → 完成后回填
```

| 环节 | 实现 |
|---|---|
| 生成 | `POST /api/reminders/generate`（AI 生成今日提醒） |
| 送达 | `POST /api/reminders/{id}/send`：**通道留空=自动** —— 优先已启用的订阅（企业微信/Webhook），否则落**本地收件箱**（`server/data/notifications.jsonl`）→ **零配置也能送到** |
| 留痕 | 回写 `reminders.sent_at / send_channel / send_ok / send_error`，同时写投递日志 `notification_logs` |
| 自动重试 | 每日心跳 `heartbeat.push_pending_reminders()`：把"未完成且未送达"的提醒再投一次（成功即不再重发） |
| 回填 | `POST /api/reminders/{id}/done`（完成后不再补发） |

> 与旧的差别：**不是"AI 给了建议"，而是"这件事被送达、被记录、没送达会自动再来一次"。**

## 三、ROI：替老板省了多少（参考估算）

> ⚠️ 人力价与替代比例是**可配置的参考估算**（`config.ROI_LABOR` / `ROI_SUGGESTED_PRICE_YUAN`，
> 也可在 `config.local.json` 覆盖）；**AI 成本是本机真实用量**（按 token × 当前模型单价）。

| 岗位 | 市场参考价 | 替代比例 | 省下/月 |
|---|---:|---:|---:|
| 代账会计 | 500 元/月 | 60% | 300 元 |
| 朋友圈文案 | 300 元/月 | 80% | 240 元 |
| 熟客维系/客服 | 1,500 元/月 | 30% | 450 元 |
| 经营参谋/店长助理 | 4,000 元/月 | 20% | 800 元 |
| **合计** | — | — | **1,790 元/月** |

对照算力成本（演示数据实测）：约 **0.08 元/月**（AI 调用极少时）→ **净省 ≈ 1,790 元/月**。
> 真实经营规模下 AI 成本会上升（如每天几十次调用），但仍远低于替代的人力价；
> 具体数字以 `/api/metrics/ai` 的 `roi` 分块为准（它用你的真实用量算）。

### 定价草案（一页商业画布用）

| 档位 | 内容 | 建议价 |
|---|---|---|
| 免费 | 记账/账本/算税/保本线（无 AI Key 也可用） | 0 元 |
| **AI 版** | 多 agent 文案/复盘/画像、主动触达、自动送达 | **99 元/月**（毛利 ≈ 99%，按演示用量） |
| 多店版 | 一店一库 + 总部视图（待做） | 按店数加价 |

> 定价逻辑：以"**替代岗位省下的 1,790 元/月**"为锚，99 元 = 省下金额的 **5.5%**，店主极易接受。

## 四、诚实边界（避免评审追问翻车）

1. 上表人力价为**区间参考**，不同城市差异大；替代比例是**保守估计**，不是实测结论。
2. AI 成本随用量变化；演示数据下极低是因为调用少，**不要当作长期成本**。
3. 熟客提醒的"自动送达"在**未配置企业微信/Webhook 时落到本地收件箱**（可查，但不是手机上收到消息）；
   要让店主手机真的收到，需按 `docs/api-reference.md` 配置企业微信群机器人（无需正式 AppID）。
4. 进化层（"越用越懂你"）**默认关闭**，不能对外宣称已自我进化（见 `deliverables/进化能力研究与优化方案.md`）。
